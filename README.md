# GRØNTALS.NO

Интернет-витрина блочных конструкторов для норвежского рынка. Без корзины и онлайн-оплаты — заказ по телефону. Технически это один Cloudflare Worker (TypeScript) с базой D1, хранилищем изображений R2 и небольшой админ-панелью на `/admin`.

Эта инструкция написана для человека без опыта программирования. Все команды даны в готовом для копирования виде — просто вставляйте их в терминал по очереди.

---

## 1. Что нужно установить один раз

1. **Node.js** (версия 18 или новее) — https://nodejs.org, скачать LTS-версию и установить как обычную программу.
2. Проверить, что всё установилось. Откройте терминал (в Windows — PowerShell) в папке проекта и выполните:
   ```
   node --version
   npm --version
   ```
   Оба должны напечатать номер версии, а не ошибку.
3. Аккаунт на https://dash.cloudflare.com (бесплатного плана достаточно для старта).

Всё остальное (Wrangler — консольный инструмент Cloudflare) ставится автоматически на следующем шаге.

---

## 2. Первый запуск с нуля

Выполняйте команды по порядку в папке проекта.

### 2.1. Установить зависимости

```
npm install
```

### 2.2. Войти в Cloudflare

```
npx wrangler login
```

Откроется браузер — войдите в свой аккаунт Cloudflare и разрешите доступ.

### 2.3. Создать базу данных (D1)

```
npx wrangler d1 create grontals-db
```

Команда напечатает блок с `database_id`, например:

```
database_id = "1a2b3c4d-...."
```

Скопируйте этот id. Откройте файл **`wrangler.jsonc`** и вставьте его вместо `REPLACE_WITH_D1_DATABASE_ID` — **в двух местах** (в начале файла и в блоке `env.production` ближе к концу — это один и тот же id в обоих местах, база одна, просто сайт открывается по двум разным адресам).

### 2.4. Создать хранилище для фотографий (R2)

```
npx wrangler r2 bucket create grontals-product-images
```

Ничего вставлять никуда не нужно — имя бакета в `wrangler.jsonc` уже совпадает.

### 2.5. Задать секретный ключ для входа в админку

Скопируйте файл-пример:

```
cp .dev.vars.example .dev.vars
```

(В Windows PowerShell: `Copy-Item .dev.vars.example .dev.vars`)

Сгенерируйте случайный ключ и вставьте его в `.dev.vars` вместо `replace-with-a-random-32-byte-hex-string`:

```
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Файл `.dev.vars` — секретный, в git он не попадёт (это уже настроено).

### 2.6. Обновить типы после правок в wrangler.jsonc

Каждый раз после изменения `wrangler.jsonc` выполняйте:

```
npm run cf-typegen
```

### 2.7. Применить структуру базы данных (локально)

```
npm run db:migrate:local
```

### 2.8. Добавить демо-товары (необязательно, но удобно для проверки)

```
npm run db:seed:local
```

### 2.9. Создать первого администратора

Замените `МойПароль123` на свой пароль:

```
npm run db:create-admin -- admin МойПароль123
```

Логин — `admin` (можно указать любое другое имя первым аргументом). Пароль хранится в базе только в хешированном виде.

### 2.10. Запустить сайт локально

```
npm run dev
```

Откройте в браузере:
- **http://localhost:8787** — сайт
- **http://localhost:8787/admin** — админка (логин/пароль из шага 2.9)

Остановить сервер — `Ctrl+C` в терминале.

### 2.11. Проверить, что всё в порядке

```
npm test
npm run typecheck
```

Оба должны завершиться без ошибок (красного текста).

## 3. Как устроен проект (кратко)

```
worker/        — весь backend: API, рендеринг страниц, админка (TypeScript)
src/           — клиентский JS: прогрессивное улучшение сайта + сама админ-панель
shared/        — типы и утилиты, общие для backend и фронтенда
migrations/    — структура базы данных D1 (SQL)
scripts/       — резервное копирование, создание админа, seed-данные
public/        — статика: собранные JS-файлы, картинка-заглушка, security-заголовки
test/          — автотесты (запускаются через `npm test`)
wrangler.jsonc — вся конфигурация Cloudflare (база, хранилище, домены, переменные)
```

Главная страница и страница товара рендерятся сервером (SSR) — это важно для поисковиков и скорости. Модалка товара поверх каталога — это лишь надстройка поверх обычных ссылок: с выключенным JavaScript всё продолжает работать через обычные переходы между страницами.

## 4. Повседневная работа

### 4.1. Админка

Зайдите на `/admin`, войдите под своим логином/паролем. Там можно:
- добавлять/редактировать/скрывать товары;
- менять цену, старую цену, наличие;
- загружать фотографии (перетащить в область загрузки — браузер сам уменьшит и сожмёт фото перед отправкой);
- менять порядок фотографий (первая по порядку = главная на карточке товара);
- добавлять характеристики (материал, размеры и т.п.);
- задавать SEO-заголовок/описание вручную (если не заданы — генерируются автоматически).

Товар с флагом «Utsolgt» (нет в наличии) не удаляется из каталога и продолжает индексироваться поисковиками — просто кнопка заказа заменяется на пометку «нет в наличии», чтобы не терять накопленный SEO-вес страницы.

### 4.2. Резервное копирование базы

Перед крупными изменениями делайте бэкап:

```
npm run db:backup
```

Файл появится в папке `backups/` (в git не попадает). Для бэкапа продакшн-базы:

```
npm run db:backup -- --remote
```

## 5. Первый деплой (тестовый адрес)

Проект деплоится как Cloudflare Worker со статикой — **не** как Cloudflare Pages. Это значит, что тестовый адрес будет вида `https://grontals.ваш-поддомен.workers.dev`, а не `*.pages.dev`.

```
npm run deploy
```

В выводе команды будет строка вида:

```
https://grontals.<account-subdomain>.workers.dev
```

Скопируйте этот адрес и вставьте его в `wrangler.jsonc` вместо `https://grontals.YOUR-SUBDOMAIN.workers.dev` (в самом верху, в блоке `vars`). Затем:

```
npm run cf-typegen
npm run deploy
```

(Повторный деплой нужен, чтобы canonical-ссылки, sitemap.xml и структурированные данные указывали на правильный адрес.)

На этом тестовом адресе индексация поисковиками **выключена** по умолчанию (`DISALLOW_INDEXING=true`) — это ожидаемо, сайт ещё не готов к публикации.

Не забудьте применить миграции и создать администратора на реальной (не локальной) базе — это одна и та же база что для тестового, что для боевого адреса (см. следующий раздел, шаги повторять не нужно дважды):

```
npm run db:migrate:remote
npm run db:create-admin -- admin МойПароль123 --remote
```

## 6. Подключение домена grøntals.no

### 6.1. Добавить домен в Cloudflare

1. В панели Cloudflare: **Websites → Add a domain** → введите `grøntals.no`.
2. Cloudflare покажет два адреса DNS-серверов (nameservers). Зайдите у вашего регистратора домена в настройки DNS и укажите там эти nameservers вместо старых.
3. Подождите активации зоны в Cloudflare (обычно от нескольких минут до пары часов).

### 6.2. Настроить секрет для боевого окружения

Секреты задаются отдельно для каждого окружения:

```
npx wrangler secret put ADMIN_SESSION_SECRET
npx wrangler secret put ADMIN_SESSION_SECRET --env production
```

Для значения используйте тот же генератор, что и в шаге 2.5 (можно тот же ключ, можно новый — главное не путать: если ключ поменяется, все, кто залогинен в админку, будут разлогинены).

### 6.3. Деплой боевой версии

```
npm run deploy:production
```

Эта команда использует `PUBLIC_SITE_URL = https://xn--grntals-r1a.no` (punycode-запись `grøntals.no`) и `DISALLOW_INDEXING=false` — они уже прописаны в `wrangler.jsonc` в блоке `env.production`, ничего вручную не собирайте.

### 6.4. Привязать домен к Worker'у

В панели Cloudflare: **Workers & Pages → grontals → Settings → Domains & Routes → Add → Custom domain** → введите `grøntals.no` (и при необходимости `www.grøntals.no`). Cloudflare сам выпустит SSL-сертификат.

### 6.5. Чек-лист перед тем, как объявить сайт «живым»

Пройдите по пунктам после деплоя на боевой домен:

- [ ] `grøntals.no` открывается по https и показывает сайт (не старую заглушку, не ошибку).
- [ ] `wrangler.jsonc` → `env.production.vars.PUBLIC_SITE_URL` = `https://xn--grntals-r1a.no`, а не workers.dev-адрес.
- [ ] `wrangler.jsonc` → `env.production.vars.DISALLOW_INDEXING` = `"false"`.
- [ ] `https://grøntals.no/robots.txt` — содержит `Sitemap:` и **не** содержит `Disallow: /` (полного запрета).
- [ ] `https://grøntals.no/sitemap.xml` — открывается, содержит реальные товары с правильным доменом в ссылках.
- [ ] Открыть исходный код главной страницы и страницы товара — проверить `<link rel="canonical">` указывает на `grøntals.no`, а не на workers.dev.
- [ ] На странице товара есть блок `<script type="application/ld+json">` с `"@type":"Product"`.
- [ ] Заполнены страницы `/om-oss`, `/kontakt`, `/personvern`, `/vilkar` — реальными данными владельца (в коде сейчас плейсхолдеры-заглушки с пометкой `[Sett inn ...]`, см. `worker/templates/legal.ts`).
- [ ] Телефон (`ORDER_PHONE_NUMBER`) в `wrangler.jsonc` — настоящий, не `+47 000 00 000`.
- [ ] Создан админ-пользователь на боевой базе (шаг 5, `--remote`), пароль-плейсхолдер `test-password-123` / `МойПароль123` заменён на настоящий, локальные тестовые товары из seed-данных удалены или отредактированы через `/admin`.

## 7. Google Search Console и аналитика

### 7.1. Search Console (рекомендуемый способ — без изменения кода)

1. https://search.google.com/search-console → Add property → `grøntals.no`.
2. Выберите способ подтверждения **DNS record** — Google покажет TXT-запись.
3. Добавьте эту запись в Cloudflare: **DNS → Records → Add record**, тип `TXT`.
4. Подтвердите в Search Console, затем отправьте `https://grøntals.no/sitemap.xml` в разделе Sitemaps.

Способ через HTML-тег тоже подготовлен: впишите значение `content="..."` (которое даёт Google) в `wrangler.jsonc` → `GSC_VERIFICATION_META`, задеплойте — тег появится автоматически на всех страницах.

### 7.2. Аналитика

**Cloudflare Web Analytics** (проще, без кода, не требует правки CSP): в панели Cloudflare — **Analytics & Logs → Web Analytics → Add site** — включается на уровне зоны, ничего в проекте менять не нужно.

**Google Analytics 4** (если нужен именно он): впишите свой ID (`G-XXXXXXXXXX`) в `wrangler.jsonc` → `GA4_MEASUREMENT_ID`, задеплойте. Скрипт GA4 и разрешения Content-Security-Policy для него подключаются автоматически только когда это поле не пустое — по умолчанию его нет вообще, и CSP остаётся максимально строгим.

## 8. Частые проблемы

**После `npm run dev` сайт открывается, но стили/JS не работают, `/admin` пустой.**
Клиентские скрипты (`public/main.js`, `public/admin.js`) собираются отдельно и не хранятся в git. `npm run dev` и `npm run deploy` пересобирают их автоматически — если открыли сайт как-то иначе, сначала выполните `npm run build:client`.

**После правки `wrangler.jsonc` посыпались ошибки типов (`Property 'DB' is possibly undefined'` и подобные).**
Выполните `npm run cf-typegen` — типы окружения генерируются из `wrangler.jsonc` и должны обновляться после каждой правки этого файла.

**Ошибка `no such table: products` при локальном запуске.**
Миграции не применены — выполните `npm run db:migrate:local`.

**Логин в админку падает с ошибкой 500.**
Не задан `ADMIN_SESSION_SECRET` — проверьте, что файл `.dev.vars` существует и содержит непустое значение (шаг 2.5), либо что секрет задан на сервере (`wrangler secret put ADMIN_SESSION_SECRET`, шаг 6.2).

**Задеплоил командой `npm run deploy`, а на реальном домене изменений нет.**
`npm run deploy` деплоит тестовое (staging) окружение. Для боевого домена нужна отдельная команда: `npm run deploy:production`.

**Загрузка фото в админке выдаёт ошибку.**
Разрешены только JPEG, PNG и WebP, максимум 5 МБ на файл — браузер сам сжимает фото перед отправкой, но исходный формат должен быть одним из этих трёх.

**Нужно откатить/посмотреть содержимое базы напрямую.**
`npx wrangler d1 execute grontals-db --local --command "SELECT * FROM products;"` (уберите `--local` для боевой базы — с осторожностью).
